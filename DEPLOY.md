# Deploying SilverConnect — full walkthrough

This app now has a real backend (Supabase: Postgres + instant API) and needs
two things set up before it works: the database, and a live URL to host the
files. Both are free and take about 10 minutes total.

---

## Part 1 — Create your Supabase project (~3 min)

1. Go to **https://supabase.com** and click **Start your project** → sign up
   (GitHub login is fastest).
2. Click **New project**.
   - Name: `silverconnect` (or anything)
   - Database password: generate/save one (you won't need to type it again)
   - Region: pick whatever is closest to your users
3. Click **Create new project** and wait ~1–2 minutes while it provisions.

## Part 2 — Create the database tables (~2 min)

1. In the left sidebar, click **SQL Editor** → **New query**.
2. Open `schema.sql` from this folder, copy the *entire* file, and paste it
   into the editor.
3. Click **Run** (bottom right). You should see "Success. No rows returned."
   - This creates the `users`, `families`, `checkins`, and `moods` tables,
     locks them down with Row Level Security, and adds the database
     functions the app calls (register, login, check-in, etc), **including
     the "Add Family Member" migration** that lets a caretaker link to more
     than one senior account.

> Already ran an older version of `schema.sql` before? Just paste and run
> the whole file again — every statement is written to be safe to re-run
> (`create table if not exists`, `create or replace function`, etc), so it
> will simply add what's missing.

## Part 3 — Connect the app to your project (~1 min)

1. In Supabase, go to **Project Settings** (gear icon) → **API**.
2. Copy the **Project URL** and the **anon public** key.
3. Open `config.js` in this folder in any text editor and paste them in:
   ```js
   window.SUPABASE_URL = "https://xxxxxxxx.supabase.co";
   window.SUPABASE_ANON_KEY = "eyJhbGciOi...";
   ```
4. Save the file.

> The anon key is *meant* to be public/shipped in client code — Supabase's
> security model relies on the Row Level Security + functions in
> `schema.sql`, not on hiding this key.

## Part 4 — Test it locally (~1 min)

Just double-click `index.html` to open it in your browser. You should see
the Welcome screen (not the "backend not connected" screen). Try:
1. **Create an Account** → Senior → fill in details → set a PIN → you'll get
   a real 6-digit Family Code generated by your database.
2. Log out, **Create an Account** → Caretaker → enter that Family Code to
   link the accounts.
3. Log back in as the senior and tap the **I'm Okay** button, or share a
   mood on the Status tab.
4. Log in as the caretaker — you should see the real check-in/mood you just
   sent, pulled live from Supabase.

If something's off, open your browser's DevTools console (F12) — network
errors usually mean `config.js` has a typo, or `schema.sql` didn't finish
running.

## Part 5 — Deploy to a live URL (~1 min)

1. Go to **https://app.netlify.com/drop**
2. Drag this whole folder onto the page.
3. Netlify gives you a live URL instantly, like `https://random-name.netlify.app`.

That's it — anyone with that link can register, log in, and use the real,
backed-by-a-database app from their phone. On mobile they can also tap
"Add to Home Screen" to install it like a native app (thanks to
`manifest.json` + `sw.js`).

### Want a custom domain or ongoing updates?
- Create a free Netlify account and claim that first deploy, so re-dragging
  the folder later updates the same URL instead of making a new one.
- Or connect Netlify to a GitHub repo for automatic deploys on every push —
  useful once you're iterating on the code regularly.

### Alternative hosts (same static files work anywhere)
- **Vercel**: `npx vercel` from inside this folder (needs a free account)
- **GitHub Pages**: push the folder to a repo → Settings → Pages → enable
- **Cloudflare Pages**: same drag-and-drop flow as Netlify

## What's still worth knowing

- **Security model**: PINs are hashed with bcrypt (`pgcrypto`) inside
  Postgres — the browser never sees a raw or hashed PIN, only pass/fail from
  the `login` function. That's solid for a real MVP, though production apps
  handling sensitive health data would typically add rate-limiting and a
  proper session/JWT layer instead of a plain phone+PIN check per request.
- **Multiple family members**: a caretaker can now link to more than one
  senior — after logging in, open the profile menu → **Add Family Member**,
  enter a name/label and the senior's Family Code. Both the Heartbeat and
  Status tabs show one card per linked senior.
- **Third-party redirects**: every marketplace link (Amazon products, Klook
  tours) now shows a confirmation pop-up before leaving the app — similar to
  the interstitial Hong Kong banks show before redirecting to third-party
  sites — stating SilverConnect has no control over or liability for that
  site.
- **Personal Information Collection Statement (PICS)**: available from the
  Login and Registration screens, and required reading (checkbox) before
  finishing registration. It references Hong Kong's Personal Data (Privacy)
  Ordinance (Cap. 486) and its six Data Protection Principles. **This is a
  template, not legal advice** — have a qualified HK lawyer or privacy
  professional review and customise it before real-world use.
- **Data resets**: nothing resets anymore — everything lives in your
  Supabase project's Postgres database permanently (until you delete it).
